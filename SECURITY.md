# Security Policy

## Supported Versions

Sigflo is currently in active development.

Security updates will be provided for the latest version of the project.

Older versions may not receive security fixes.

## Reporting a Vulnerability

If you discover a security vulnerability, please report it responsibly.

Please do not open a public GitHub issue for security vulnerabilities.

Instead, contact the maintainers directly at **support@sigflo.group** with:

- A description of the vulnerability
- Steps to reproduce
- Potential impact
- Any suggested mitigations (if known)

We will acknowledge receipt of security reports as quickly as possible and work to investigate and resolve confirmed issues.

## Responsible Disclosure

We ask that security researchers:

- Give maintainers a reasonable amount of time to investigate and resolve issues before public disclosure.
- Avoid accessing, modifying, or deleting data that does not belong to you.
- Avoid actions that could negatively impact users or project infrastructure.

We appreciate responsible disclosure and value the contributions of the security community.

## Scope

Examples of security vulnerabilities include:

- Authentication bypasses
- Authorization issues
- Privilege escalation
- Sensitive data exposure
- Remote code execution
- Injection vulnerabilities
- Credential leakage
- API security flaws

Examples generally considered out of scope include:

- Missing security headers
- Version disclosure
- Best-practice recommendations without a demonstrable security impact
- Issues requiring physical access to a device

## Security Practices

Sigflo follows several security principles:

- Secrets are never committed to source control.
- Sensitive credentials should be stored in environment variables.
- Dependencies should be kept up to date.
- Security-related issues are prioritized.
- User data should be handled with the principle of least privilege.

## Safe Use of Sigflo

Users are responsible for:

- Protecting their exchange credentials
- Using strong passwords
- Enabling two-factor authentication where available
- Understanding the risks associated with trading and automated trading systems

## Disclaimer

Sigflo is provided on an "as-is" basis without warranties of any kind.

While we strive to maintain a secure platform, no software can be guaranteed to be completely free from vulnerabilities.

Users should carefully evaluate risks before connecting live trading accounts or deploying automated trading strategies.
